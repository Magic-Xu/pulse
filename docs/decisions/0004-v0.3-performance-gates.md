# ADR 0004: Pulse v0.3 Performance Gates

- Status: Accepted
- Target version: 0.3.0
- Scope: release verification

## Decision

The release harness runs the same simple reducer workload against a frozen v0.2 synchronous
reference and the v0.3 ordered engine. It records throughput, p95 frame latency, a bounded-mailbox
admission count, cancelled-subscription memory delta, delivery latency to a real transition
collector, and emissions from the real `StateFlow.selectDistinct` pipeline in a machine-readable
JSON report.

Correctness takes precedence over matching the lock-only v0.2 implementation. The portable CI
floor therefore rejects catastrophic regressions rather than normal coroutine overhead:

- v0.3 throughput must remain at least 0.5% of the v0.2 reference workload;
- p95 sequential frame completion must remain below 100ms;
- mailbox high-water must never exceed configured capacity;
- the 10,000-subscription cancel workload must retain less than 64MiB after forced collection;
- transition collector delivery p95 must remain below 20ms;
- the selector pipeline must emit exactly the semantic-distinct count implied by its workload.

The mailbox metric is a capacity smoke test, not instrumentation of every internal queue state. The
selector metric executes the platform-neutral selector used by non-Compose consumers; Compose owns
separate lifecycle and recomposition tests. Collector latency measures the controlled harness lane,
not device rendering. The harness is intended to catch catastrophic regressions on a portable CI
runner, not to establish device performance or comprehensive microbenchmark evidence.

The synchronous v0.2 reference omits the v0.3 mailbox, frame, task, plugin, and effect boundaries, so
its throughput is not a like-for-like target. Release review must retain both the measured ratio and
this cost explanation. The v0.3 implementation keeps the ordered design; optimization work should
profile allocation and coroutine hand-offs without weakening ordering or failure isolation.

Release review keeps the full report as an artifact. Tightening a threshold requires measurements on
the same CI runner class and an ADR update; a threshold may not be relaxed silently.
